## 1. 概述

本设备（DT12，汽车电瓶检测 / 维修工具）通过 **USB CDC（虚拟串口）** 与 PC 上位机通信，并支持通过 **WiFi 模块（ESP32）** 与云端 / APP 交互。通信内容涵盖：身份认证、版本查询、万用表测量数据、电流曲线数据、开机日志、CAN 总线实时透传、多路 UART 数据桥接以及固件升级（IAP）。

### 1.1 通信通道总览

| 通道 | 物理介质 | 方向 | 用途 |
| --- | --- | --- | --- |
| USB CDC | USB Full-Speed，CDC-ACM | 双向 | 主通道：命令交互、数据上报、固件升级 |
| WiFi | MCU UART3 ↔ ESP32C3 | 双向 | 云端 / APP 数据交互、透传、OTA |
| UART 桥接 | UART0/1/2/4/5 | 上行 | 车辆总线日志数据转发至 USB |
| CAN | CAN0 / CAN1 | 双向 | 车辆总线诊断；可透传至 USB |

## 2. USB CDC 主通道

### 2.1 链路特性

- 枚举为 CDC-ACM 虚拟串口（FT232 兼容模式），与波特率无关。
- 发送侧采用 **12 KB 环形缓冲**（`UPDATE_TXRX_SIZE = 12288`），单包最大 60 字节，每轮最多发送 64 包。
- 连接判定：USB 枚举完成（Configured）且 **DTR 置位**。
- 连接建立 / 断开时清空收发缓冲；断开时自动关闭 UART 桥接。
- 连接期间每 **20 ms** 发送一次底层 keep-alive。
- 若 TX 超过 **300 ms** 无就绪（上位机停止收取），自动关闭桥接并清空缓冲（防卡死）。

### 2.2 消息约定

- 命令/应答均为 **ASCII 字符串**，无二进制帧头。
- 命令匹配采用 **前缀匹配**（接收长度 ≥ 命令长度且前 N 字节相等），上位机命令可携带 `\r\n` 等尾部字符。
- 通用成功应答：`JC_OK`。

### 2.4 上行数据（设备 → 上位机）

#### 2.4.1 万用表测量数据（JSON）

- 触发：万用表电压/二极管模式，且投屏开启（`ScreenFlag = true`），周期 **25 ms**。
- 按键 / 命令单次触发（`g_record_upload_pending`）时立即发送一次，不受周期限制。

电压模式：

```json
{"type":"voltage","value":"12.3400"}
```

二极管模式：

```json
{"type":"resis","value":"0.6700"}
```

投屏模式（区分显示流与记录流）：

```json
{"type":"screen_v","value":"12.3400"}
{"type":"screen_r","value":"0.6700"}
```

- `type` 取值：`voltage`（电压）、`resis`（二极管）、`screen_v`（投屏电压）、`screen_r`（投屏二极管）。
- `value` 为浮点字符串，4 位小数（`%.4f`），单位 V。
- 发送入口：`board_pack_buf_data()` → USB TX 环形缓冲，无追加换行。

#### 2.4.2 电流曲线数据（INA260 采样）

- 触发：电流曲线页（`CURRENT_CURVE_PAGE`）+ 上传开关（`bootup_upload_flag = true`），周期 **36 ms**。
- INA260 在线（`online`）时才发送。

```json
{host:{T:52085},out:{{S:0,V:0.000,I:0.000},{S:0,V:0.000,I:0.000},{S:0,V:0.000,I:0.000},{S:1,V:12.340,I:1.230}}}
```

- `T:52085`：协议类型标识（固定）。
- `out` 数组共 4 个采样点，`S` 为序号（0~3），当前有效数据在第 4 点（`S:1`），其余为占位 0。
- `V` 单位 V，`I` 单位 A，3 位小数（`%.3f`）。
- 行尾带 `\r\n`。

#### 2.4.3 开机日志页 INA260 数据

- 触发：开机日志页（`BOOT_LOG_PAGE`）且 UART 桥接 mask 非 0（上位机已连接），周期 **36 ms**。

```json
{host:{T:52085},{V:12.340,I:1.230}}
```

- 与电流曲线共用 `T:52085` 标识，行尾带 `\r\n`。

#### 2.4.4 CAN 总线实时透传（文本行）

- 触发：CAN 总线页（`CAN_BUS_PAGE`）且 USB 已连接，CAN 中断入队后由任务批量发送。
- 每帧一行，格式：

```
%08lu CAN%u %s %s 0x%0*lX %u [D0 D1 ... D7]
```

| 字段 | 说明 |
| --- | --- |
| `%08lu` | FreeRTOS tick（约 ms），8 位十进制 |
| `CAN%u` | 通道号（0 / 1） |
| 帧格式 | `STD` / `EXT` |
| 帧类型 | `DATA` / `RTR` |
| `0x%X` | ID；标准帧 3 位宽，扩展帧 8 位宽 |
| `%u` | 数据长度（0~8） |
| 数据字节 | 大写十六进制，空格分隔 |

示例：

```
00012345 CAN0 STD DATA 0x600 8 02 10 03 55 55 55 55 55
```

- 队列深度 128 帧，每轮最多发送 24 帧，批量缓冲 1 KB，USB 预留 128 字节空间。
- 队列溢出时丢弃最旧帧并累计丢帧计数（`can_usb_passthrough_get_drop_frames()`）。

#### 2.4.5 UART 桥接数据（Marker 帧）

- 触发：开机日志页 + UART 桥接开启，5 路 UART（0/1/2/4/5）DMA 接收数据。
- 帧格式：**Marker + 原始数据 + Marker**（无长度字段）：

```
~J!C@I#D$U^1 <原始数据> ~J!C@I#D$U^1
```

| 通道 | Marker |
| --- | --- |
| UART0 | `~J!C@I#D$U^1` |
| UART2 | `~J!C@I#D$U^2` |
| UART5 | `~J!C@I#D$U^3` |
| UART4 | `~J!C@I#D$U^4` |
| UART1 | `~J!C@I#D$U^5` |

- 组帧模式：定长模式（满 256 字节立即发送）或超时模式（500 ms 无数据发送短帧）。
- 双缓冲乒乓切换，USB 空间不足时反压暂停采集。
- ⚠️ 注意：当前协议 **未对数据中出现的 Marker 序列做转义处理**，若原始串口数据恰好包含 Marker 会造成分帧歧义。

#### 2.4.6 ESP32 透传（上行）

- ESP32 收到 MCU_TO_PC（type = 0xAA）类数据时，由设备转发至上位机：

```
JC_from_esp32:<ESP32原始数据>
```

- 行尾追加 `\r\n`；仅 USB 已连接时转发。

#### 2.4.7 系统日志

- 格式：` [文件名] : [函数] : [行号] : 消息\n`（`usb_printf` / `USB_LOG`）。

## 3. 固件升级（IAP）

### 3.1 Boot 区升级（USB 通道，`usb_driver.c`）

流程：

```
上位机                         设备
   |  JC_boot_upgrade_start      |
   |--------------------------->|  进入升级态，回 JC_OK
   |  第一包: CRC16(2B) + 数据   |
   |--------------------------->|  回 JC_OK
   |  数据包 ...                 |
   |--------------------------->|  回 JC_OK（每包）
   |  JC_boot_upgrade_end        |
   |--------------------------->|  CRC 校验 → JC_boot_ok / JC_boot_fail
```

- 首包前 2 字节为固件 CRC16（大端），其后为固件数据。
- 数据连续写入 SRAM 缓冲（`sramBuff`），每包应答 `JC_OK`。
- 异常应答：`ERR: Invalid First Packet`（首包 < 2 字节）、`ERR: SRAM Full`（缓冲溢出）。
- 结束包触发校验：`crc16(sramBuff, sramBuffLen)` 与首包 CRC 比对。
  - 成功：回 `JC_boot_ok`，擦除 `0x08000000`、`0x08004000` 两扇区，写入固件，100 ms 后重启。
  - 失败：回 `JC_boot_fail`。

### 3.2 APP 区升级（`app_iap.c`）

- 升级目标：APP 起始地址 `0x08010000`（`APP_START_ADDRESS`），最大尺寸 `APP_MAX_SIZE`。
- **Bin 信息头（96 字节）**：

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 32 | logo | 须等于 `JCID` |
| 32 | 32 | type | 须等于 `JCID_DT12` |
| 64 | 32 | vers | 版本字符串 |
| 96 | 4 | size | 固件大小，大端（BE） |
| 100 | 2 | crc | CRC16（大端） |

- 数据接收：缓冲满 2 KB 写一次 Flash（4 字节对齐）；全部写完后整体 CRC 校验。
- 校验失败返回 `IAP_ERR_CRC`；logo/type 不符返回 `IAP_ERR_BIN_INFO`。
- 支持 USB 与 WiFi 两种模式（`IAP_MODE_USB` / `IAP_MODE_WIFI`）。

## 4. WiFi 通信协议（MCU ↔ ESP32C3）

物理层：UART3 + DMA，收发缓冲 4 KB。

### 4.1 帧格式（小端，头部 7 字节 + Payload + CRC8）

```
+------+------+------------+------------+--------------+---------+-----------+----------+
| cmd  | type | totalLen   | protocolVer| encryptionVer| reserve | payload   | crc8     |
| 1B   | 1B   | 2B (LE)    | 1B         | 1B           | 1B      | 可变       | 1B       |
+------+------+------------+------------+--------------+---------+-----------+----------+
```

- `totalLen` = payload 长度 + 8（头部 7 字节 + CRC 1 字节）。
- `crc8` 覆盖 `totalLen - 1` 字节（头部 + payload），多项式 0x07（查表实现）。
- `type` 取值：

| type | 含义 |
| --- | --- |
| `0x00` | WIFI_TO_MCU（ESP32 → MCU） |
| `0xAA` | MCU_TO_PC（MCU → ESP32 → PC/云） |
| `0xBB` | WIFI_TO_MCU_SPEC（ESP32 → MCU 专用） |

### 4.2 命令列表

#### MCU → ESP32（上行）

| type | cmd | 功能 | Payload |
| --- | --- | --- | --- |
| 0xAA | 0x01 | 属性响应（设备名/唯一ID/软件版本/硬件版本/安全版本/运行状态） | 属性索引 + 长度 + 值 |
| 0xAA | 0x02 | 命令响应 | 可变 |
| 0xAA | 0x03 | 控制：下载固件 / 查询 APP 版本 / 开关 WiFi / AP 控制 | `{0,0,x,0,0}` 5 字节 |
| 0xAA | 0x04 | AP 模式控制 | 9 字节 |
| 0xAA | 0x20 | 实时测量数据（JSON） | `{"type":"voltage","value":"12.3400"}` 等 |
| 0xAA | 0x40 | 升级应答（0=成功 / 1=允许 / 2=拒绝） | 1 字节 |
| 0x00 | 0x01 | 查询属性（0x50 版本 / 0x54 名称 / 0x55 功率） | 1 字节属性索引 |
| 0x00 | 0x02 | 查询 WiFi 名称 | 1 字节 |
| 0x00 | 0x04 | AP 控制（0x53 开头 9 字节） | 9 字节 |

#### ESP32 → MCU（下行）

| type | cmd | 功能 | Payload 说明 |
| --- | --- | --- | --- |
| 0x00 | 0x01/0x02 | 属性响应 | `attr(1B) + len + 值` |
| 0x00 | 0x03 | 控制命令 | 见下 |
| 0x00 | 0x04 | 查询响应（APP 版本） | `0x59` 开头 + 版本串 |
| 0x00 | 0x20 | 心跳 / 状态 | `4B 头 + WifiState` |
| 0x00 | 0x43 | 传输状态通知（OTA 进度） | `fileSize@34`、`curSize@38`（LE） |
| 0xBB | 0x01/0x02 | 专用属性响应 | 同 0x00/0x01 |

**0x00/0x03 控制命令 payload 语义（rx[2]）**：

| rx[2] | 功能 |
| --- | --- |
| 0x01 / 0x02 | 切换万用表二极管 / 电压测量模式 |
| 0x01 / 0x02 | 开启 / 关闭开机电压电流上传（`wifi_upload_flag`） |
| 0x01 / 0x02 | 开启 / 关闭投屏（`wifi_screen_flag`） |

**心跳状态 WifiState（`drv_wifi.h`）**：

```c
typedef struct {
  uint8_t level;      // WiFi 信号强度
  uint8_t blueState;  // 蓝牙状态
  uint8_t sendSwitch; // 实时测量数据发送开关（=2 时才发送）
  uint8_t state;      // 连接状态（=3 已联网）
} WifiState;
```

### 4.3 实时数据上报

- 万用表测量：`wifi_upload()` / `wifi_screen_upload()`，发送条件 `sendSwitch == 2 && state == 3`，type=0xAA、cmd=0x20，payload 为 JSON（格式同 2.4.1）。
- 开机电压电流：`wifi_upload_bootup()`，payload 同 2.4.2 的 `{host:{T:52085},out:{...}}` 格式。
